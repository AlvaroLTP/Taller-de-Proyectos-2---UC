# Modelo de Datos — EcoLogística Lima

## 1. Modelo Conceptual: Diagrama Entidad-Relación Conceptual

El modelo conceptual define las entidades de negocio críticas para la plataforma **"EcoLogística Lima"** y sus interacciones, garantizando el soporte operativo para la gestión de flota y pedidos en Lima Metropolitana.

### Entidades principales

- **Usuario:** Entidad central de autenticación y autorización para acceder a la plataforma (Administradores, Gestores de ruta, Clientes, Conductores).
- **Vehículo:** Representa a las unidades físicas (camionetas, furgones, motos) de la flota de DistriRápido S.A.C., almacenando sus características de capacidad y factores de emisión.
- **Conductor:** Registra al personal operativo encargado de ejecutar las entregas, sujeto a normativas laborales de tiempo y disponibilidad.
- **Cliente:** Representa a los pequeños comerciantes y bodegas que solicitan las entregas, incluyendo sus preferencias de horarios.
- **Pedido:** Elemento central de la operación. Contiene los detalles de la mercadería, la ubicación geoespacial de entrega y las restricciones temporales (ventanas de tiempo).

### Relaciones principales

- Un **Usuario** puede tener un perfil asociado de **Conductor** o **Cliente** (Relación 1:1 o 1:0).
- Un **Cliente** realiza uno o muchos **Pedidos** (Relación 1:N).
- Un **Conductor** es asignado a un **Vehículo** para realizar una ruta específica (Relación N:M gestionada por la entidad transaccional `Ruta_Asignacion` en el futuro).

## 2. Modelo Lógico: Especificación y Nivel de Normalización (3FN)

Todas las tablas han sido diseñadas cumpliendo la **Tercera Forma Normal (3FN)**, asegurando que todos los atributos no clave dependan única y exclusivamente de la **Clave Primaria (PK)**.

### Entidad: `usuarios`

- **PK:** `usuario_id` (UUID)
- **Atributos:**
  - `email`
  - `password_hash`
  - `estado`
  - `creado_en`

### Entidad: `vehiculos`

- **PK:** `vehiculo_id` (UUID)
- **Atributos:**
  - `placa`
  - `tipo`
  - `capacidad_carga_kg`
  - `consumo_km_l`
  - `factor_emision_co2`
  - `anio_fabricacion`
  - `estado`

### Entidad: `conductores`

- **PK:** `conductor_id` (UUID)
- **FK:** `usuario_id` (Referencia a `usuarios.usuario_id`)
- **Atributos:**
  - `nombre_completo`
  - `dni`
  - `licencia_categoria`
  - `anios_experiencia`
  - `disponibilidad_horaria`
  - `telefono_contacto`

### Entidad: `clientes`

- **PK:** `cliente_id` (UUID)
- **FK:** `usuario_id` (Referencia a `usuarios.usuario_id`)
- **Atributos:**
  - `nombre_razon_social`
  - `preferencias_horarias`
  - `referencias_acceso`

### Entidad: `pedidos`

- **PK:** `pedido_id` (UUID)
- **FK:** `cliente_id` (Referencia a `clientes.cliente_id`)
- **Atributos:**
  - `direccion_texto`
  - `coordenadas_gps` (Tipo Geometry/Point)
  - `peso_kg`
  - `volumen_m3`
  - `ventana_inicio`
  - `ventana_fin`
  - `prioridad`
  - `tipo_producto`
  - `estado_entrega`

## 3. Modelo Físico (DDL SQL - PostgreSQL + PostGIS) e Índices

A continuación, el script DDL para desplegar la base de datos, incorporando los estándares de seguridad y tipos de datos espaciales necesarios para nuestro optimizador.

```sql
-- Habilitar extensión PostGIS para datos geoespaciales
CREATE EXTENSION IF NOT EXISTS postgis;

-- 1. Tabla usuarios (Estructura Base Requerida)
CREATE TABLE usuarios (
    usuario_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    estado VARCHAR(20) NOT NULL DEFAULT 'ACTIVO',
    creado_en TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_usuarios_email ON usuarios(email);

-- 2. Tabla vehiculos
CREATE TABLE vehiculos (
    vehiculo_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    placa VARCHAR(15) NOT NULL UNIQUE,
    tipo VARCHAR(50) NOT NULL,
    capacidad_carga_kg DECIMAL(10,2) NOT NULL,
    consumo_km_l DECIMAL(10,2) NOT NULL,
    factor_emision_co2 DECIMAL(10,4) NOT NULL,
    anio_fabricacion INTEGER NOT NULL,
    estado VARCHAR(20) DEFAULT 'OPERATIVO',
    creado_en TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_vehiculos_placa ON vehiculos(placa);

-- 3. Tabla conductores
CREATE TABLE conductores (
    conductor_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    usuario_id UUID NOT NULL,
    nombre_completo VARCHAR(255) NOT NULL,
    dni VARCHAR(15) NOT NULL UNIQUE,
    licencia_categoria VARCHAR(20) NOT NULL,
    anios_experiencia INTEGER NOT NULL,
    disponibilidad_horaria VARCHAR(100),
    telefono_contacto VARCHAR(20),
    CONSTRAINT fk_conductor_usuario
        FOREIGN KEY (usuario_id)
        REFERENCES usuarios(usuario_id)
        ON DELETE CASCADE
);

CREATE INDEX idx_conductores_dni ON conductores(dni);

-- 4. Tabla clientes
CREATE TABLE clientes (
    cliente_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    usuario_id UUID NOT NULL,
    nombre_razon_social VARCHAR(255) NOT NULL,
    preferencias_horarias TEXT,
    referencias_acceso TEXT,
    CONSTRAINT fk_cliente_usuario
        FOREIGN KEY (usuario_id)
        REFERENCES usuarios(usuario_id)
        ON DELETE CASCADE
);

-- 5. Tabla pedidos
CREATE TABLE pedidos (
    pedido_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    cliente_id UUID NOT NULL,
    direccion_texto TEXT NOT NULL,
    coordenadas_gps GEOMETRY(Point, 4326) NOT NULL, -- PostGIS SRID 4326 (WGS 84)
    peso_kg DECIMAL(10,2) NOT NULL,
    volumen_m3 DECIMAL(10,2) NOT NULL,
    ventana_inicio TIME NOT NULL,
    ventana_fin TIME NOT NULL,
    prioridad VARCHAR(20) DEFAULT 'ESTANDAR',
    tipo_producto VARCHAR(50),
    estado_entrega VARCHAR(30) DEFAULT 'PENDIENTE',
    creado_en TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_pedido_cliente
        FOREIGN KEY (cliente_id)
        REFERENCES clientes(cliente_id)
        ON DELETE CASCADE
);

-- Índice espacial GIST para acelerar cálculos de distancias y ruteo
CREATE INDEX idx_pedidos_coordenadas
    ON pedidos USING GIST (coordenadas_gps);

CREATE INDEX idx_pedidos_estado
    ON pedidos(estado_entrega);
```
