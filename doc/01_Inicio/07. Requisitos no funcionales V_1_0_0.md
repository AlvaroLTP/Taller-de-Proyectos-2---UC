## 1. Propósito

Este documento especifica los Requisitos No Funcionales (RNF) del sistema **EcoLogística Lima**, estableciendo atributos de calidad medibles mediante escenarios de calidad.

La definición de los RNF se estructura bajo el enfoque de **ISO/IEC 25010 / arc42**, utilizando escenarios compuestos por:

- Fuente
- Estímulo
- Entorno
- Artefacto
- Respuesta
- Medida o SLA

Las métricas se expresan mediante umbrales cuantitativos verificables, siguiendo el criterio SMART establecido para el proyecto.

## 3. Escenarios de Calidad

### RNF-001: Rendimiento

**Categoría ISO/IEC 25010:** Rendimiento

**Fuente:** Usuario autorizado del sistema.

**Estímulo:** Solicitud de generación de una ruta optimizada para un conjunto de hasta 150 pedidos y 15 vehículos.

**Entorno:** Operación normal del sistema durante el horario operativo.

**Artefacto:** Módulo de generación y optimización de rutas.

**Respuesta:** El sistema procesa los pedidos, vehículos y restricciones correspondientes y genera una solución válida de rutas optimizadas.

**Medida / SLA:**

- La solución válida debe generarse en un tiempo máximo de **45 segundos** para problemas de hasta **150 pedidos y 15 vehículos**.
- Ante modificaciones durante horas punta, la re-optimización debe completarse en menos de **30 segundos**.

---

### RNF-002: Seguridad

**Categoría ISO/IEC 25010:** Seguridad

**Fuente:** Usuario externo no autorizado o atacante.

**Estímulo:** Intento de explotación de vulnerabilidades web, incluyendo inyección SQL, XSS, CSRF o intentos de autenticación no autorizados.

**Entorno:** Sistema desplegado y operativo.

**Artefacto:** Módulos de autenticación, API y componentes de acceso a datos.

**Respuesta:** El sistema debe rechazar las solicitudes maliciosas, impedir el acceso no autorizado y mantener la integridad de la información.

**Medida / SLA:**

- **0 vulnerabilidades críticas explotables** identificadas relacionadas con el OWASP Top 10 en la evaluación de seguridad.
- Los datos personales de clientes y conductores deben gestionarse conforme a la **Ley N.° 29733, Ley de Protección de Datos Personales del Perú**.

---

### RNF-003: Accesibilidad

**Categoría ISO/IEC 25010:** Usabilidad / Accesibilidad

**Fuente:** Conductor, cliente o administrador con limitaciones visuales, motrices o de interacción tecnológica.

**Estímulo:** El usuario interactúa con las funciones de consulta y operación del sistema.

**Entorno:** Uso normal de la plataforma web.

**Artefacto:** Interfaz de usuario y componentes de interacción.

**Respuesta:** La interfaz debe permitir la interacción y consulta de las funcionalidades disponibles utilizando criterios de accesibilidad.

**Medida / SLA:**

- Cumplimiento de las directrices **WCAG 2.1 nivel AA**.
- Los elementos principales de interacción deben utilizar iconografía de tamaño suficiente y contraste visual adecuado.
- La interfaz debe permitir la utilización de las funciones principales sin depender exclusivamente de elementos visuales.

---

### RNF-004: Escalabilidad

**Categoría ISO/IEC 25010:** Eficiencia del desempeño / Capacidad

**Fuente:** Crecimiento de la operación logística de DistriRápido S.A.C.

**Estímulo:** Incremento del volumen diario de pedidos y de la cantidad de vehículos gestionados.

**Entorno:** Operación del sistema con crecimiento de la demanda.

**Artefacto:** Plataforma web, servicios de procesamiento y almacenamiento de datos.

**Respuesta:** El sistema debe mantener su operación al incrementar progresivamente la cantidad de pedidos y vehículos.

**Medida / SLA:**

- El sistema debe soportar hasta **1,000 pedidos diarios**.
- El sistema debe soportar hasta **50 vehículos**.
- La arquitectura debe permitir la expansión de la operación hacia los distritos de **Los Olivos, Comas e Independencia**.

---

### RNF-005: Usabilidad

**Categoría ISO/IEC 25010:** Usabilidad

**Fuente:** Conductor con nivel básico de educación formal o experiencia limitada con sistemas digitales.

**Estímulo:** El conductor accede a la información correspondiente a su jornada de reparto.

**Entorno:** Operación diaria del sistema desde la interfaz destinada al conductor.

**Artefacto:** Modo conductor del sistema.

**Respuesta:** El sistema debe presentar únicamente la información necesaria para que el conductor consulte y ejecute su ruta asignada.

**Medida / SLA:**

El modo conductor debe mostrar como mínimo:

1. Ruta asignada.
2. Entregas pendientes.
3. Alertas de tráfico.

La interfaz debe utilizar una estructura simplificada, iconos grandes y elementos visuales de alto contraste, conforme a las condiciones establecidas para el proyecto.

---

### RNF-006: Disponibilidad

**Categoría ISO/IEC 25010:** Fiabilidad / Disponibilidad

**Fuente:** Usuario operativo del sistema.

**Estímulo:** Solicitud de acceso a la plataforma durante el horario de operación logística.

**Entorno:** Horario operativo comprendido entre las **5:00 AM y 10:00 PM**.

**Artefacto:** Plataforma web y componentes necesarios para su funcionamiento.

**Respuesta:** El sistema debe permanecer disponible para permitir la ejecución de las operaciones logísticas.

**Medida / SLA:**

- Disponibilidad mínima de **99.5 %** durante el horario operativo.
- Debe existir un mecanismo de contingencia ante interrupciones de energía o conectividad.
- La estrategia de contingencia debe considerar la posibilidad de disponer de información de respaldo local en dispositivos móviles.

---

### RNF-007: Documentación

**Categoría ISO/IEC 25010:** Mantenibilidad

**Fuente:** Equipo de desarrollo, administradores y usuarios responsables del sistema.

**Estímulo:** Necesidad de comprender, administrar, mantener o utilizar el sistema.

**Entorno:** Durante el desarrollo, operación y mantenimiento de EcoLogística Lima.

**Artefacto:** Documentación técnica y funcional del proyecto.

**Respuesta:** El proyecto debe proporcionar documentación que permita comprender el funcionamiento, arquitectura, operación y componentes de la solución.

**Medida / SLA:**

La documentación debe incluir como mínimo:

- Proceso de desarrollo.
- Arquitectura del sistema.
- Manual de usuario.
- Manual de administrador.
- Documentación de la API.
- Análisis del contexto logístico de Lima.
- Características de las vías.
- Horas punta.
- Normativa de tránsito aplicable.

## 5. Relación con el Contexto de EcoLogística Lima

Los RNF se establecen considerando las condiciones operativas descritas para **DistriRápido S.A.C.**, particularmente el volumen de entregas, la congestión vehicular, las horas punta de Lima, las necesidades de los conductores y las condiciones de disponibilidad de infraestructura.

El requisito de rendimiento considera que el tráfico presenta variaciones importantes durante las horas punta, estableciendo un límite específico para la generación y re-optimización de rutas.

El requisito de escalabilidad considera el crecimiento proyectado de la operación hacia **1,000 pedidos diarios y 50 vehículos**.

La accesibilidad y usabilidad consideran que algunos conductores pueden presentar limitaciones en el uso de tecnología, por lo que se establece un modo conductor simplificado.

La disponibilidad contempla el horario operativo de **5:00 AM a 10:00 PM** y la posibilidad de interrupciones de energía en determinadas zonas de Lima.

La seguridad considera la protección de los datos de clientes y conductores y la aplicación de **OWASP Top 10** y la **Ley N.° 29733**.

## 7. Criterio de Validación

Cada requisito no funcional deberá validarse mediante una métrica cuantificable o un criterio verificable. No se considerará suficiente utilizar únicamente términos cualitativos como “rápido”, “seguro”, “escalable”, “fácil” o “eficiente” sin establecer el umbral correspondiente.

La validación de los RNF se realizará mediante pruebas de rendimiento, seguridad, accesibilidad, carga, disponibilidad y revisión documental, según corresponda.
