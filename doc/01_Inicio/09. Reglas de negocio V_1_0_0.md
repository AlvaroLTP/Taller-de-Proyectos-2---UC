# Reglas de Negocio y Trazabilidad

# 1. Codificación de Reglas de Negocio

## RN-001: Validación de información de vehículos

El sistema debe validar que un vehículo cuente con placa, tipo, capacidad de carga, consumo de combustible, factor de emisión de CO₂ y año de fabricación antes de permitir su incorporación a la flota.

**Requisito funcional asociado:** RF-001 **Requisito no funcional asociado:** RNF-002

## RN-002: Validación de información de pedidos

El sistema debe requerir la información necesaria del pedido antes de incorporarlo a la planificación de rutas, incluyendo cliente, dirección o referencia de entrega, coordenadas GPS, peso, volumen, ventana de tiempo, prioridad y tipo de producto.

**Requisito funcional asociado:** RF-002 **Requisito no funcional asociado:** RNF-002

## RN-003: Validación previa a la generación de rutas

El sistema no debe generar una planificación de rutas cuando no exista información suficiente de pedidos, vehículos o restricciones necesarias para obtener una solución válida.

**Requisito funcional asociado:** RF-003 **Requisito no funcional asociado:** RNF-001

## RN-004: Criterios de optimización de rutas

La generación de rutas debe considerar como criterios de optimización la distancia total, tiempo total, consumo de combustible, emisiones de CO₂, penalizaciones por entregas tardías y restricciones relacionadas con el descanso de los conductores.

**Requisito funcional asociado:** RF-003 **Requisito no funcional asociado:** RNF-001

## RN-005: Cumplimiento de ventanas de tiempo

Las rutas generadas deben considerar las ventanas de tiempo establecidas para las entregas y minimizar las penalizaciones derivadas del incumplimiento de los horarios acordados.

**Requisito funcional asociado:** RF-003 **Requisito no funcional asociado:** RNF-001

## RN-006: Consideración del tráfico

Cuando exista información disponible sobre tráfico o incidentes, el sistema debe utilizarla como una condición para la generación o re-optimización de las rutas.

**Requisito funcional asociado:** RF-003 / RF-007 **Requisito no funcional asociado:** RNF-001

## RN-007: Visualización de rutas

Una ruta optimizada debe poder visualizarse mediante un mapa interactivo mostrando el trazado, los puntos de entrega, el tiempo estimado por tramo y el nivel de congestión disponible.

**Requisito funcional asociado:** RF-004 **Requisito no funcional asociado:** RNF-003

## RN-008: Clasificación del nivel de congestión

Cuando exista información de congestión, el sistema debe representar el nivel correspondiente mediante las categorías visuales establecidas para el proyecto: verde, amarillo y rojo.

**Requisito funcional asociado:** RF-004 **Requisito no funcional asociado:** RNF-005

## RN-009: Cálculo de indicadores de sostenibilidad

Los indicadores del sistema deben calcularse a partir de los datos disponibles de operación, incluyendo distancia recorrida, emisiones de CO₂, combustible ahorrado, cumplimiento de ventanas de tiempo y ahorro frente a una ruta secuencial.

**Requisito funcional asociado:** RF-005 **Requisito no funcional asociado:** RNF-001

## RN-010: Validación de datos para indicadores

Cuando no existan datos suficientes para calcular un indicador, el sistema no debe presentar valores calculados incorrectamente y deberá informar que la información necesaria no está disponible.

**Requisito funcional asociado:** RF-005 **Requisito no funcional asociado:** RNF-002

## RN-011: Generación de reportes de sostenibilidad

Los reportes de sostenibilidad deberán generarse únicamente cuando exista información suficiente para elaborar el resumen de emisiones, costos y demás indicadores definidos para el reporte.

**Requisito funcional asociado:** RF-006 **Requisito no funcional asociado:** RNF-007

## RN-012: Re-optimización ante eventos

Cuando ocurra un nuevo pedido, una cancelación, un accidente de tránsito o una avería de vehículo, el sistema deberá permitir recalcular las rutas afectadas considerando las nuevas condiciones.

**Requisito funcional asociado:** RF-007 **Requisito no funcional asociado:** RNF-001

## RN-013: Disponibilidad de conductores

La asignación de rutas debe considerar la disponibilidad horaria registrada para cada conductor y las restricciones de jornada y descanso establecidas para la operación.

**Requisito funcional asociado:** RF-007 / RF-008 **Requisito no funcional asociado:** RNF-001

## RN-014: Preferencias de entrega de clientes

Las preferencias registradas por los clientes, incluyendo horarios, puntos de referencia y restricciones de acceso, deben ser consideradas durante la planificación de las entregas cuando la información se encuentre disponible.

**Requisito funcional asociado:** RF-009 **Requisito no funcional asociado:** RNF-005

## RN-015: Cálculo de compensación de carbono

El sistema debe calcular las emisiones totales de CO₂ disponibles y utilizar dicho resultado para generar una propuesta de compensación mediante alternativas de reforestación consideradas por el proyecto.

**Requisito funcional asociado:** RF-010 **Requisito no funcional asociado:** RNF-001

## RN-016: Protección de datos personales

La información personal de clientes y conductores debe gestionarse aplicando medidas de seguridad y controles de acceso que eviten accesos no autorizados.

**Requisito funcional asociado:** RF-001 / RF-008 / RF-009 **Requisito no funcional asociado:** RNF-002

## RN-017: Control de acceso por roles

El sistema debe limitar el acceso a funcionalidades e información de acuerdo con el rol asignado a cada usuario.

**Requisito funcional asociado:** RF-001 / RF-002 / RF-008 / RF-009 **Requisito no funcional asociado:** RNF-002

# 3. Reglas de validación y consistencia

Las reglas de negocio deberán considerarse durante el análisis, diseño, implementación y pruebas del sistema.

Para cada regla se deberá verificar que:

1. La condición establecida sea comprensible y verificable.
2. La regla pueda relacionarse con al menos un requisito funcional.
3. Cuando corresponda, la regla pueda relacionarse con un requisito no funcional.
4. Las reglas relacionadas con datos personales sean consideradas dentro de los controles de seguridad.
5. Las reglas relacionadas con optimización sean verificadas mediante pruebas funcionales y de rendimiento.
6. Las reglas relacionadas con indicadores sean verificadas mediante datos de prueba conocidos.
7. Las reglas relacionadas con roles sean verificadas mediante pruebas de control de acceso.
