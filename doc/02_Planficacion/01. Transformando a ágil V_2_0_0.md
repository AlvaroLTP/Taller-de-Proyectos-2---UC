# A1. Transformando a ágil V_1_A_A

## 1. Definition of Done (DoD) Global del Proyecto

Para asegurar la calidad técnica y el cumplimiento de los Requisitos No Funcionales del proyecto, ninguna Historia de Usuario (US) o Enabler será considerada como finalizada ("Done") hasta cumplir los siguientes criterios:

1. **Cobertura de Pruebas:** Cobertura de pruebas unitarias y de integración ≥ 80%, verificada en el pipeline de CI/CD.
2. **Seguridad y Calidad de Código:** Análisis estático mediante SonarQube/CodeQL con 0 vulnerabilidades críticas o mayores, considerando OWASP Top 10 y la Ley N.° 29733.
3. **Revisión de Código:** Pull Request aprobado por al menos un integrante técnico del equipo.
4. **Despliegue Continuo:** Despliegue exitoso en el ambiente de Staging/Pruebas.
5. **Documentación:** Documentación técnica y de API actualizada mediante OpenAPI/Swagger cuando corresponda.
6. **Accesibilidad:** Las interfaces desarrolladas cumplen los criterios aplicables de WCAG 2.1 nivel AA.
7. **Criterios de Aceptación:** Todos los criterios de aceptación definidos para la Story o Enabler han sido verificados satisfactoriamente.
# 2. Mapa de Épicas

Los Requisitos Funcionales han sido agrupados en tres Épicas de desarrollo:

### EP-01: Gestión Core de Operaciones Logísticas

Comprende la gestión de la información necesaria para las operaciones logísticas.

### Requisitos asociados:

- RF-001 Gestión de Flota

### Requisitos asociados:

### Requisitos asociados:

- RF-004 Visualización de Rutas en Mapa
