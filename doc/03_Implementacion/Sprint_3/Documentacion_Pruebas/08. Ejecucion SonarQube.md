## 3. Plan de Remediación y Deuda Técnica

- **Deuda Técnica Estimada:** **No disponible en la evidencia exportada.** No se consigna un tiempo estimado sin consultar la métrica `sqale_index` o el detalle equivalente en SonarQube.
- **Prioridad inmediata:** elevar la cobertura del código nuevo desde 16.7% hasta el umbral aprobado de 80%.
- **Alcance prioritario:** Frontend, cuyas pruebas cubren principalmente utilidades y cliente HTTP, mientras páginas, store y servicios críticos permanecen con cobertura insuficiente.

### Principales hallazgos y acciones correctivas

1. **Cobertura insuficiente del código nuevo — Quality Gate fallido.**
   - Añadir pruebas de componentes, contexto/store, autorización, servicios y páginas críticas.
   - Incorporar casos negativos, errores HTTP y estados de carga.
   - Regenerar LCOV y Cobertura XML antes de repetir el scanner.

2. **132 code smells pendientes de clasificación y tratamiento.**
   - Exportar el listado completo con regla, archivo, línea, severidad/impacto y esfuerzo.
   - Priorizar primero los hallazgos bloqueantes y altos, si existieran.
   - Corregir por lotes pequeños y ejecutar pruebas después de cada lote.

3. **Cobertura Frontend desproporcionadamente baja.**
   - Conservar las pruebas actuales de utilidades y cliente HTTP.
   - Añadir pruebas de los flujos que manejan pedidos, vehículos, planificación, rutas y permisos cuando la integración real esté disponible.
   - No usar mocks como única evidencia de integración Frontend–Backend.

4. **Quality Gate todavía no apto para aceptación.**
   - No reducir el umbral solamente para obtener un estado aprobado.
   - Reejecutar TypeScript, build, pytest, Vitest y SonarQube sobre el mismo commit candidato.
   - Conservar el identificador de tarea y la respuesta final del servidor.
