## 1. Resumen ejecutivo

El proyecto contiene una aplicación React funcional conectada directamente a Supabase, un backend FastAPI con endpoints CRUD y una interfaz de monitoreo correspondiente al Sprint 3. Sin embargo, no existe integración efectiva entre React y FastAPI: el frontend consulta y modifica las tablas mediante `@supabase/supabase-js`, incluida la generación simulada y persistencia de rutas.

La arquitectura implementada es:

```text
React -> Supabase Auth + Supabase Database

FastAPI -> PostgreSQL/Supabase mediante DATABASE_URL
```

La arquitectura documentada, todavía no alcanzada, es:

```text
React -> FastAPI REST -> PostgreSQL/PostGIS
                       -> motor de optimización
                       -> adaptador de tráfico/mapas
```

Las funciones del Sprint 3 son demostrativas o parciales:

- el mapa es un SVG calculado localmente, no Leaflet/OpenStreetMap;
- la congestión se infiere por cantidad de paradas por distrito;
- los indicadores se calculan en el navegador;
- los ahorros se estiman con multiplicadores constantes;
- el proveedor de tráfico del backend siempre informa que no está disponible;
- el generador backend valida solo listas vacías y entrega colecciones vacías al optimizador;
- el optimizador es una agrupación demostrativa de seis pedidos y no persiste resultados.

Por tanto, no corresponde declarar el Sprint 3 como integrado ni los requisitos de calidad como cumplidos.

## 9. Autenticación y autorización

### Autenticación

- El frontend usa `supabase.auth.signInWithPassword()`.
- La sesión se restaura y refresca con Supabase Auth.
- Los perfiles contienen los roles `admin`, `operator` y `driver`.
- React muestra rutas diferentes para conductor y administración/operación.

### Riesgos de autorización

1. El control de rutas React es únicamente un control de presentación.
2. FastAPI no valida tokens Supabase/JWT y no aplica RBAC.
3. Las políticas RLS finales conceden `SELECT`, `INSERT`, `UPDATE` y `DELETE` a cualquier usuario autenticado sobre todas las tablas operativas.
4. Un conductor autenticado puede intentar modificar recursos administrativos directamente mediante la API de Supabase.
5. La migración de usuarios contiene una contraseña de demostración estática y compartida en el historial del repositorio.

Esto constituye un riesgo crítico de control de acceso. Si la migración fue aplicada en un entorno, debe planificarse la rotación de esas credenciales. La auditoría estática no confirma si dichas cuentas existen actualmente en producción.

## 10. CORS y variables de entorno

Backend:

- `DATABASE_URL` tiene valor predeterminado vacío.
- CORS permite por defecto `http://localhost:5173` y `http://127.0.0.1:5173`.
- `allow_credentials=True`, `allow_methods=['*']` y `allow_headers=['*']`.
- `.env.example` documenta `DATABASE_URL`, `CORS_ORIGINS`, `APP_NAME` y `DEBUG`.
- `database.py` lee `DATABASE_URL` directamente con `os.getenv`, mientras `config.py` también lo declara; hay dos fuentes de configuración.
- El ejemplo de `CORS_ORIGINS` usa una cadena separada por comas para un campo `List[str]`; debe comprobarse su parseo real con `pydantic-settings`.

Frontend:

- usa `VITE_SUPABASE_URL` y `VITE_SUPABASE_ANON_KEY`;
- no existe `.env.example` frontend;
- no existe `VITE_API_BASE_URL`.

## 13. Evaluación específica del Sprint 3

### US-017 — Visualización de rutas

Existe representación de rutas y paradas, pero se proyectan coordenadas manualmente sobre SVG. No se visualizan calles, geometría de ruta, tiempos por tramo ni capas OSM. Resultado: **parcial/solo frontend**.

### US-018 — Congestión

Los niveles Alta/Media/Baja dependen del número relativo de paradas por distrito. El título aclara que no es tráfico en tiempo real. El backend devuelve tráfico no disponible. Resultado: **demostrativo, no integrado**.

### US-019 — Indicadores

Se muestran rutas, entregas, tiempos, utilización y emisiones. Los cálculos ocurren en React y algunos datos son estáticos. No existe endpoint de métricas, persistencia histórica ni evidencia de exactitud. Resultado: **parcial**.

### US-020 — Ahorros

Se presentan ahorros de distancia, tiempo, combustible, costo y CO2. La base de comparación se construye multiplicando los valores “optimizados” por factores fijos. No hay escenario base persistido. Resultado: **simulado**.
